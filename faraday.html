The headline result: 0.48 → 1.00, Cross-process agreement of NeMo-Relay's reuse fingerprint over 20 processes, before and after NVIDIA/NeMo-Relay#481, the merged fix this idea led to. Control: main at 2ab7a070 with no source change: 0.479, as reported in the PR. Code: teerthsharma/faraday on GitHub.

What it is

Faraday is an idea I am still testing, and the name of the repository where I test it. Here is the idea. Take one object and describe it in two ways. Learn a linear operator that carries the first description to the second. Then look at the operator’s dominant direction, the one that repeated application settles on, and treat it as the structure the two descriptions share. If both descriptions really come from the same object, that direction should belong to the pair, not to either description alone.

The test case is electromagnetic. A resonant mode of a cavity has an electric field and a magnetic field, and Maxwell’s curl equations tie them together. Faraday summarises each field the same way, topologically. It then fits a map from the E summaries to the H summaries across many cavities and runs that map until its direction stops changing. The repository calls the resulting unit vector the “God Tensor”. In this essay I call it x∗x^\astx∗.

The repository is a work in progress. The current code runs the pipeline end to end on rectangular and circular cavities with perfectly conducting walls. It does not yet realise the fixed-point and topological framing the README describes, and section 6 says where it falls short. So this essay is about three things: the idea, how I am trying it in code, and where it has already been useful. It is not a report of a result. The idea’s first concrete use is outside electromagnetics: it gave me the idea for a fix that is now merged into NVIDIA’s NeMo-Relay.

Faraday shares no code with my electromagnetic field simulator. The two have one habit in common: they threshold a field and summarise what is left.

What it can do

What the idea would make possible

If the idea holds, it buys three things.

The first is a compact operator that records which features of one description go with which features of the other. The README calls this a “reduced-order coupling model”. For cavity fields it would mean a 16×16 matrix in place of a solver, as a summary of how E-field structure maps onto H-field structure across a family of geometries.

The second is a single reference vector. A fixed direction of the operator does not depend on any one training example. The README proposes to use it “as a semantic anchor, same as NLP models use [CLS] tokens”, as a shared coordinate that new examples can be compared against.

The third is a test of shared structure. If two descriptions come from the same object, both should map towards the same direction under the operator. If they do not, the gap between where they land can be measured. That turns “these two views agree” from an impression into a number.

None of the three is demonstrated yet for cavity fields; section 6 gives the current state. The idea has, however, already done work elsewhere.

Where the idea has already been used

merged into NVIDIA/NeMo-Relay #481 · 2026-08-10

fix(adaptive): reuse stable ACG scaffolds

Cross-process agreement of the reuse fingerprint over N = 20 processes: 0.479 on main, 1.000 on the PR head, as the PR reports it.

Faraday gave me the idea for this fix.

NVIDIA/NeMo-Relay #481teerth.dev/nemo-relay-481

Faraday gave me the idea for this fix. Here is what the fix does, in the pull request’s own terms.

NeMo-Relay’s adaptive component learns which leading part of a request stays stable across runs, so that part can be reused. On main, its learning key included the first non-system message. A workflow whose system prompt, tool schemas and output contract never change was therefore split into a separate profile for every distinct first user task. Observations never accumulated, and the stable scaffold was never recognised as a reusable prefix. The PR keys learning on that stable system, tool and structured-output scaffold and binds reuse to a fingerprint of the exact scaffold key.

Reuse also had to be deterministic across processes. A profile persisted by one process is read back by another, so the analysis must not depend on the per-process seed Rust draws for HashMap iteration. The PR measures this with a cross-process agreement rate. Run NNN processes on the same input, let the distinct outcomes occur with multiplicities c1,…,ckc_1, \dots, c_kc1​,…,ck​, and define

A=∑ici (ci−1)N (N−1).A = \frac{\sum_i c_i\,(c_i - 1)}{N\,(N - 1)} .A=N(N−1)∑i​ci​(ci​−1)​.

This is the probability that two independent processes agree. It equals 1 exactly when the analysis does not depend on the seed.

On main, an agreement of 0.479 means better than half of cross-process profile reads miss. After the change, all 20 processes agree. On the same window, 19 of 20 observations share an exact 6-block prefix, where a per-span rule reports a prefix of 1. The PR also states its own limits: it claims no provider-cache, cost or latency improvement.

The link from faraday is the one I stated above: faraday gave me the idea. Read side by side, the two ask a similar question: what stays fixed across many instances that differ in one part? In faraday the instances are cavities, and the fixed part is meant to be the direction that an E-to-H operator settles on. In NeMo-Relay the instances are requests, and the fixed part is the scaffold the PR keys learning on. That parallel is my reading of the two documents. It is not a mechanism one inherited from the other. The fix stands on the PR’s own measurement.

How it was made

DefinitionThe objects

For MMM training cavities, let ZE∈RM×16Z_E \in \mathbb{R}^{M \times 16}ZE​∈RM×16 and ZH∈RM×16Z_H \in \mathbb{R}^{M \times 16}ZH​∈RM×16 hold the learned codes of the E and H summaries, one row per cavity. The coupling operator T∈R16×16T \in \mathbb{R}^{16 \times 16}T∈R16×16 is the least-squares map with ZET⊤≈ZHZ_E T^\top \approx Z_HZE​T⊤≈ZH​. The vector x∗x^\astx∗ is the unit vector that normalised power iteration on TTT settles on, defined up to sign.

This section describes how the current code at commit 6ca4bff tries the idea. The code is a work in progress, and some parts below are placeholders for what the idea needs.

Two descriptions of one cavity mode

The solver samples cavities, 70 % rectangles and 30 % circles, and lays each on a 30×30 grid that includes the wall nodes. It assembles the five-point Laplacian with Ez=0E_z = 0Ez​=0 on the walls and asks a sparse eigensolver for the modes:

ei+1,j−2ei,j+ei−1,jΔx2+ei,j+1−2ei,j+ei,j−1Δy2=−k2 ei,j.\frac{e_{i+1,j} - 2e_{i,j} + e_{i-1,j}}{\Delta x^2} + \frac{e_{i,j+1} - 2e_{i,j} + e_{i,j-1}}{\Delta y^2} = -k^2\, e_{i,j}.Δx2ei+1,j​−2ei,j​+ei−1,j​​+Δy2ei,j+1​−2ei,j​+ei,j−1​​=−k2ei,j​.

The H description is the weakest part of the current test. The code does not solve for HHH. It derives a magnitude from EzE_zEz​ by central differences, Hx≈∣∂yEz∣/kH_x \approx \lvert \partial_y E_z \rvert / kHx​≈∣∂y​Ez​∣/k and Hy≈∣∂xEz∣/kH_y \approx \lvert \partial_x E_z \rvert / kHy​≈∣∂x​Ez​∣/k, with c=μ=1c = \mu = 1c=μ=1 and the phase factor and sign dropped. The two descriptions therefore come from the same eigenvector, and some of their agreement is built in before any learning happens. A fair test of the idea needs two descriptions that are computed independently.

From fields to codes

Each field is thresholded at 5 % of its maximum. The kept grid points become a point cloud (x/nx, y/ny, phase)(x/n_x,\, y/n_y,\, \text{phase})(x/nx​,y/ny​,phase), and Ripser computes its persistence barcode up to dimension 1. The README describes a Hilbert-series embedding of that barcode. The code currently uses something simpler, embed_fingerprint: 20 summary statistics placed into a 50-slot vector and normalised. The statistics cover bar lifetimes, bar counts and field magnitudes. Two one-layer autoencoders, one for E and one for H, compress these vectors to 16 numbers with a ReLU code. They are trained for 100 epochs with seed 42.

The coupling operator

learn_T fits the operator by least squares and transposes the result:

T⊤=arg⁡min⁡A  ∥ZEA−ZH∥F,T=ZH⊤(ZE+)⊤.T^\top = \arg\min_{A}\; \lVert Z_E A - Z_H \rVert_F, \qquad T = Z_H^\top \big(Z_E^{+}\big)^{\top}.T⊤=argAmin​∥ZE​A−ZH​∥F​,T=ZH⊤​(ZE+​)⊤.

The theory doc writes the same fit as T=ZHZE+T = Z_H Z_E^{+}T=ZH​ZE+​, with samples as columns.

This is power iteration. Normalisation removes scale, so the iteration converges to the dominant eigenvector of TTT, whatever its eigenvalue. That need not be the eigenvalue-1 vector the docstring defines, and the logged step size cannot tell the two apart. In the committed run the direction stops moving after six steps, and the burn keeps logging the same direction for the remaining epochs. Turning the dominant direction into a statement about E and H takes another step the code does not yet take: checking where the E codes and the H codes each land relative to x∗x^\astx∗, and whether they land together.

What’s new in it

The usual approach, in the README’s own words, is “Maxwell’s equations → FDFD solver → E and H fields”. You solve for the fields, and any statement about how E and H relate is read from the solution. Data-driven methods add a second habit: they read dominant directions from data. Proper orthogonal decomposition takes the dominant directions of one set of snapshots. Dynamic mode decomposition takes the eigenvectors of an operator that advances one snapshot to the next.

Faraday changes what the operator connects. It fits a map from one description of a state to a different description of the same state, here E to H for one cavity mode. It then reads that map’s dominant direction as what the two descriptions share. The operator is not a time step and not a basis for one data set. It is a coupling between two views, and its fixed direction is the candidate for their common structure.

The README frames the search for that direction as “the Banach fixed-point theorem applied to learned electromagnetic topology”. Banach’s theorem needs a map fff on a complete metric space and one constant qqq that holds for every pair of points:

d(f(x),f(y))≤q d(x,y),0≤q<1.d\big(f(x), f(y)\big) \le q\, d(x, y), \qquad 0 \le q \lt 1 .d(f(x),f(y))≤qd(x,y),0≤q<1.

For faraday the map is f(x)=Tx/∥Tx∥f(x) = Tx / \lVert Tx \rVertf(x)=Tx/∥Tx∥ on the unit sphere, with xxx and −x-x−x treated as the same point. The repo’s own theory doc says this map “is not a strict contraction on the unit sphere under Euclidean distance”. What does hold is the textbook result for power iteration: it converges to the dominant direction at the rate of the ratio of the second-largest to the largest eigenvalue magnitude, ∣λ2/λ1∣\lvert \lambda_2 / \lambda_1 \rvert∣λ2​/λ1​∣. The figure shows what Banach’s condition asks of this map, and where a normalised linear map meets it.

So the new part is not the numerical method, which is power iteration. The new part is what the method is pointed at: an operator fitted between two descriptions of one object, with its dominant direction read as a property of the pair. The README says as much about the physics: the convergence is “not a novel physical result”.

What no one else built

The idea, stated once more: fit a linear operator from one learned representation of a system to another learned representation of the same system, then treat the operator’s dominant direction as the structure the two share. Each part has close prior work. I name it part by part, then state what is left.

Reduced-order modelling and POD. Proper orthogonal decomposition (Berkooz, Holmes and Lumley, 1993) builds a low-dimensional basis from field snapshots by singular value decomposition. Its dominant directions are directions of one data set. Faraday’s learned codes fill the role a POD basis would. They are learned from summaries of a barcode instead of from the field.

Dynamic mode decomposition. DMD (Schmid, 2010) fits the least-squares linear operator A=YX+A = Y X^{+}A=YX+ between two snapshot matrices and reads its eigenvectors as modes. Faraday’s T=ZHZE+T = Z_H Z_E^{+}T=ZH​ZE+​ is the same construction, with the “next snapshot” YYY replaced by the second description of the same state. The eigen-analysis that follows is DMD’s, reduced to one eigenvector by power iteration.

Koopman operator learning. Koopman theory (Mezić, 2005) studies dynamics through a linear operator on observables. Extended DMD (Williams, Kevrekidis and Rowley, 2015) fits that operator in a dictionary of functions. Lusch, Kutz and Brunton (2018) learn the observables with an autoencoder and fit a linear operator in the latent space, trained jointly. This is the closest prior work to faraday’s architecture. Faraday differs in three concrete ways. It uses two encoders, one per description, where Lusch et al. use one. It trains the encoders first and fits the operator afterwards. And its operator maps across descriptions instead of advancing time. The repo does not yet show that any of these differences helps, and the second may well hurt: with separate training, nothing ties the codes to the operator.

Physics-informed operator learning. DeepONet (Lu et al., 2021) and the Fourier neural operator (Li et al., 2020) learn maps between function spaces and are judged by how well they predict the output field. Faraday does not predict a field. Its operator acts on summaries, so it cannot be compared with these methods on their own terms.

Barcodes as features. Persistence images (Adams et al., 2017) turn a barcode into a vector with a stability guarantee. Faraday’s current summary vector is ad hoc statistics with no such guarantee.

What is left is narrow, and I state it narrowly. I have not found, in the work above, the move of pairing two descriptions of the same state as the source and target of a DMD-style fit and reading the dominant eigenvector as their shared structure. I do not claim that no one has made it. Faraday does not yet show that the move measures anything physical for cavity fields.

The idea’s value so far is downstream. Faraday gave me the idea for NVIDIA/NeMo-Relay#481. That fix is merged, and its result is the PR’s own: cross-process agreement of 0.479 on main and 1.000 after.

Limitations

Faraday is a work in progress, and its README describes more than the current code does. The README frames the method as a Banach fixed point. The code runs normalised power iteration, which finds the dominant eigenvector of TTT and logs a step size that is blind to the eigenvalue. The README’s “Betti-0/1/2 errors” are, in the code, the mean, spread and third moment of the cosines between the mapped E codes and x∗x^\astx∗, not topological quantities. The H codes are computed next to them and not yet used. The README describes a Hilbert-series embedding, while the code uses summary statistics. It describes a 3D dielectric solver, while the code solves the 2D scalar problem for EzE_zEz​ in perfectly conducting rectangles and circles. The H field is derived from E rather than computed independently. Some README examples, including the CLI commands and the ledger hash audit, do not yet match the code. There are no Lean proofs. The history available to me is a single commit. Until the code checks where E and H each land relative to x∗x^\astx∗, using two independently computed descriptions, the idea is untested on its own example. The repo’s own wording is that “no scaling experiment has been performed”.
